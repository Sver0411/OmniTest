# 成员、团队与项目角色（v0.5.0）

在既有管理员配置凭据基础上，增加可由界面管理的成员和团队。每个成员使用独立访问令牌，团队为成员授予项目角色；不需要共享管理员令牌，也不要求接入模型。

## 启用

共享账户必须先配置管理员管理 API 凭据，再启动服务。支持原 OMNITEST_API_TOKEN 或具有 admin 角色的 access_tokens。首次部署应保留独立的启动管理员凭据，避免依赖某个可被停用的成员账户。

未配置认证的本地模式仍可使用原有测试功能，“成员与团队”会提示先配置管理员凭据，不会默默启用共享账户。数据库已有成员／团队时移除认证配置会导致启动失败，避免降级为匿名管理员。

管理员在“成员与团队”新建成员，设置用户名、显示名称、启用状态、可选全局管理员和直接项目角色。创建及轮换令牌时只显示一次，服务端仅保存 SHA-256 摘要，不提供重新读取明文的接口。令牌具有随机高熵值，前缀为 `omt_`；列表、审计和备份不保存其明文。请通过自己选择的方式交付凭据。

成员在“系统设置”填入该令牌，仍只保存到当前浏览器会话。CLI 将同一值放入客户端 OMNITEST_API_TOKEN，通过 `--url` 使用运行服务。

## 项目角色

| 项目角色 | 查看与导出 | 执行与取消 | 编辑用例、数据、目标、环境、套件和调度 |
| --- | --- | --- | --- |
| viewer | 是 | 否 | 否 |
| operator | 是 | 是 | 否 |
| editor | 是 | 是 | 是 |

全局管理员可管理全部项目、账户、团队、AI、审计和运维。普通成员不能创建／删除项目或修改自身授权。编辑者可编辑自己获准项目的名称。

成员可以在项目 A 是 editor，在项目 B 是 viewer。后端逐请求按实际资源所属项目判断权限，界面也随当前项目切换；不能把 A 的编辑权限带到 B。未分配项目时列表为空。

团队包含成员与项目角色，可独立停用。权限按直接授权和所有启用团队的最大角色合并，不提供显式拒绝规则；例如直接 viewer 加团队 operator 得到 operator。移除成员、修改／停用团队后，下一次请求立即使用新的范围。停用成员使其令牌无法认证；轮换令牌立即使旧令牌失效。

用户名在保存时转换为小写并检查唯一性。审计操作者使用 `user:USERNAME` 区分管理员文件身份；涉及项目的记录保存当时的实际角色，已提交运行保留发起人。成员／团队授权的项目不能删除，需先移除授权。管理员可禁用账户而保留历史。

已授权提交的运行与项目调度属于项目，撤销成员权限不自动取消已提交任务或删除其创建的项目资源。运行取消仍通过项目执行权限控制。

## 管理 API

以下接口只允许全局管理员：

- `GET /api/collaboration`：成员与团队安全清单，不包含令牌摘要。
- `POST /api/collaboration/members`：username、display_name、enabled、is_admin、project_roles，返回成员和一次性 token。
- `PUT /api/collaboration/members/{id}`：修改或停用成员。
- `POST /api/collaboration/members/{id}/rotate`：返回新的单次可见令牌。
- `POST /api/collaboration/teams` / `PUT /api/collaboration/teams/{id}`：name、description、enabled、project_roles、member_ids。
- `DELETE /api/collaboration/teams/{id}`：删除团队和成员关联，撤销由该团队授予的权限。

`GET /api/session?project_id=...` 和 `/api/settings?project_id=...` 返回当前项目的实际角色与按钮权限。每个成员有效范围最多 500 个项目，超限应由管理员减少授权。

新增表由迁移 0004 自动创建；旧项目、运行、审计、节点和配置保留。离线备份恢复包含成员摘要与团队关系，恢复服务仍需原有外部管理员／节点环境配置，不会把这些配置写入归档。

这套身份系统是项目管理权限，不提供密码登录、OIDC／SAML、组织邀请邮件或不信任租户之间的操作系统隔离。共享服务应通过 HTTPS 或受控代理访问；文件系统管理员、本地 CLI 和可信插件仍属于服务器管理边界。

## 验证

`backend/tests/test_members.py` 验证分项目角色、团队继承／撤销、令牌摘要／轮换／停用、拒绝提权、引用、启动拒绝降级和恢复。`scripts/acceptance_completion.py` 从实际界面创建成员与团队，检查 A 可编辑、B 只读，完成数据与远程运行后轮换令牌，最后恢复成员和历史并再次运行。截图和摘要位于忽略的 `data/completion/`，令牌不写入文件。
